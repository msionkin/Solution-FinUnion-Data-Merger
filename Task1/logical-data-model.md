# Логическая модель данных

ERD ключевых сущностей объединённого банка. Диаграмма: [diagrams/logical-data-model.mmd](diagrams/logical-data-model.mmd).

## Связи

| Связь | Кардинальность | Смысл |
|---|---|---|
| Клиент — Договор | M:N через Участие в договоре | У договора может быть несколько сторон (созаёмщик, поручитель), у клиента — много договоров |
| Продукт — Договор | 1:N | По одному продукту заключается много договоров; каждый договор — ровно по одному продукту |
| Продукт — Тариф | 1:N | У продукта несколько тарифных планов и версий |
| Договор — Счёт | 1:N | Договор открывает один или несколько счетов |
| Договор — Вклад | 1:0..1 | Договор вклада описывает один вклад |
| Договор — Кредит | 1:N | Кредитная линия может включать несколько траншей |
| Счёт — Карта | 1:N | К счёту выпускаются основная и дополнительные карты |
| Счёт — Платёж | 1:N | С одного счёта списывается много платежей; каждый платёж — с одного счёта плательщика |
| Счёт — Транзакция | 1:N | По счёту проходит много операций |
| Платёж — Транзакция | 1:N (опц.) | Платёж исполняется одной или несколькими проводками (сумма, комиссия) |
| Клиент — Обращение | 1:N | У клиента может быть много обращений |
| Договор / Счёт / Карта / Платёж — Обращение | 0..1:N | Необязательная ссылка на предмет обращения |
| Клиент — Согласие | 1:N | Согласия с разными целями и каналами |
| Сегмент — Клиент | 1:N | В сегменте много клиентов; каждый клиент на дату — в одном сегменте |
| Подразделение — Клиент / Договор | 1:N | Обслуживающее подразделение и подразделение оформления |
