# Правила владения данными

- Data Owner — руководитель бизнес-подразделения банка (указана должность). Если сущность есть у обеих линий бизнеса, владелец определяется по типу клиента или продукта: ФЛ — директор по розничному бизнесу, ЮЛ и ИП — директор по МСБ. Утверждает правила и пороги качества, согласовывает доступ, отвечает за разбор инцидентов.
- Data Steward — отвечает за ежедневное качество: разбирает ошибки проверок и спорные совпадения, ведёт справочники.
- Data Office ведёт каталог данных, методику качества и реестр владельцев.
- Правила изменения действуют только в мастер-системе. Реплики (CRM, DWH, BI, поиск) данные не меняют.
- Проверки качества идут по пяти измерениям: полнота, точность, своевременность, уникальность, консистентность.

| Сущность | Data Owner | Data Steward | Producer | Consumer | Правила изменения | Правила качества |
|---|---|---|---|---|---|---|
| Клиент | Директор по розничному бизнесу (ФЛ), директор по МСБ (ЮЛ, ИП) | Data Office (стюарды MDM) | FU CRM, RB CRM → MDM Customer Hub | FU/RB CRM, FU/RB Core, Cards, Loans, DWH, BI, риск-менеджмент | Меняется только через MDM. CRM вносит изменения, а MDM проверяет и утверждает их. Слияние дублей — автоматически при высоком совпадении, спорные случаи разбирает стюард | Уникальность UCID (доля дублей < 0,5%); полнота ФИО, ДР, ДУЛ ≥ 99%, ИНН для ЮЛ = 100%; проверка форматов ДУЛ, ИНН, СНИЛС, телефона; проверка паспорта по базе недействительных |
| Участие в договоре | Директор по розничному бизнесу (ФЛ), директор по МСБ (ЮЛ, ИП) | Операционный департамент | FU/RB Core, Loans, Cards | CRM, DWH, риск-менеджмент | Меняется только при изменении договора (допсоглашение) | У каждого договора есть владелец; UCID участника есть в MDM; роль берётся из единого справочника |
| Договор | Директор по розничному бизнесу (ФЛ), директор по МСБ (ЮЛ, ИП) | Операционный департамент | FU/RB Core, Loans, Cards | CRM, DWH, BI, контакт-центр | Меняется только в учётной системе по заявке или допсоглашению; изменения журналируются | Номер уникален в пределах банка (ключ — банк + номер); есть продукт и тариф; дата окончания не раньше даты начала; статус сверяется с CRM |
| Продукт | Директор по розничному бизнесу (розничные продукты), директор по МСБ (продукты МСБ) | Data Office (стюард справочников) | MDM (Reference Data) | Core, Cards, Loans, CRM, каналы, DWH | Новый продукт вводится решением продуктового комитета; запрещено менять код продукта, у которого есть договоры | Код уникален; для каждого продукта RB есть маппинг на продукт FU (100% к переносу портфеля) |
| Тариф | Директор по розничному бизнесу (розничные тарифы), директор по МСБ (тарифы МСБ) | Финансовый департамент | MDM (Reference Data) | Core, Cards, Loans, CRM, DWH | Меняется только новой версией с датой начала действия; прошлые версии не редактируются | Периоды версий не пересекаются; ставки в допустимых диапазонах; версия, применённая в системах, совпадает с MDM |
| Счёт | Главный бухгалтер | Операционный департамент | FU Core, RB Core | CRM, Cards, DWH, BI, регуляторная отчётность | Открывается и закрывается только в АБС | Номер по контрольному ключу ЦБ; счёт привязан к договору; сумма остатков в DWH совпадает с оборотно-сальдовой ведомостью АБС |
| Вклад | Директор по розничному бизнесу | Операционный департамент | FU Core, RB Core | CRM, DWH, BI, Финансовый департамент | Меняется только в АБС по условиям договора | Ставка соответствует тарифу; срок и дата окончания заданы; при пролонгации сохраняется история ставок |
| Кредит | Директор по розничному бизнесу (кредиты ФЛ), директор по МСБ (кредиты ЮЛ, ИП) | Риск-менеджмент (кредитное администрирование) | FU Loans, RB Loans | Core, CRM, DWH, BI, риск-менеджмент | Меняется только в Loans | Ежедневная сверка задолженности Loans и Core (расхождение 0); просрочка считается по единой методике |
| Карта | Директор по розничному бизнесу | Операционный департамент (процессинг) | FU Cards, RB Cards | Core, CRM, DWH, антифрод | Меняется только в процессинге; полный номер карты не покидает PCI-зону | Статус из единого справочника; при перевыпуске есть ссылка на прежнюю карту; в других системах только токен или маскированный номер |
| Платёж | Финансовый директор | Операционный департамент | FU Core, RB Core (из каналов) | CRM, DWH, антифрод, контакт-центр | После исполнения не меняется; ошибка исправляется только сторнированием или новым платежом | Проверка реквизитов (БИК, счёт, ИНН); уникальный ID платежа (защита от повторной отправки) |
| Транзакция | Главный бухгалтер | Финансовый департамент (сверка) | FU/RB Core, FU/RB Cards | DWH, Data Lake, BI, риск-менеджмент, антифрод | Не изменяется; ошибка исправляется только сторнирующей проводкой | Сумма проводок в DWH совпадает с АБС; есть метки времени события и загрузки; авторизация и проводка не учитываются дважды |
| Обращение клиента | Директор контактного центра | Контактный центр (контроль качества) | FU CRM, RB CRM | DWH, BI, Розничный бизнес, МСБ | Меняется в CRM по регламенту обработки обращений | Обращение привязано к UCID; тематика из единого классификатора; нет ПДн и номеров карт в тексте; срок ответа не нарушен |
| Согласие | Ответственный за организацию обработки ПДн | Data Office | FU CRM, RB CRM → Consent Management (цель) | MDM, CRM, каналы, маркетинг, DWH | Меняется только по запросу клиента; отзыв логический (soft delete) с сохранением истории | Заданы цель, срок и получатели; отзыв доходит до всех систем ≤ 15 мин; коммуникация без действующего согласия невозможна |
| Подразделение | Операционный директор | Data Office (стюард справочников) | MDM (Reference Data) | Core, CRM, DWH, BI | Открывается и закрывается приказом; код закрытого подразделения не используется повторно | Код уникален; иерархия без циклов; для каждого подразделения RB есть маппинг на FU |
| Клиентский сегмент | Директор по розничному бизнесу (ФЛ), директор по МСБ (ЮЛ, ИП) | Data Office | MDM (Reference Data) | CRM, тарифы, DWH, BI, риск-менеджмент | Методика меняется по решению бизнес-владельца; отнесение клиента хранится с историей | У каждого активного клиента есть сегмент; сегменты FU и RB приведены к единой модели |
