# Потоки данных промежуточного состояния (3 месяца)

DFD уровня 0: [diagrams/data-flow-diagram.mmd](diagrams/data-flow-diagram.mmd). Номера потоков F01–F18 совпадают на диаграмме, в этой таблице и в [data-flow-management.md](data-flow-management.md).

## Описание потоков

Действия: C — Create, R — Read, U — Update, D — Delete (логическое), E — Enrich, V — Validate, A — Aggregate.

| № | Источник | Приёмник | Сущности | Действие | Режим обмена | Зачем нужен поток |
|---|---|---|---|---|---|---|
| F01 | FU CRM | MDM (через Kafka) | Клиент | C, U → V, дедупликация | CDC | Каждое изменение клиента FU попадает в MDM для сопоставления и формирования золотой записи |
| F02 | RB CRM | MDM (через Kafka) | Клиент | C, U → V, дедупликация | CDC | То же для клиентов RB без доработки RB CRM |
| F03 | FU Core, RB Core | MDM (через Kafka) | Клиент (владельцы счетов, участники договоров) | R → V | CDC | Сопоставить клиентов, которые есть в АБС, но отсутствуют или отличаются в CRM, и построить полные кросс-ссылки UCID |
| F04 | FU CRM | MDM (через ESB) | Клиент | R | Синхронный (REST) | Перед заведением клиента проверить, нет ли его уже, в том числе среди клиентов RB, чтобы не создавать дубль |
| F05 | MDM | FU CRM, RB CRM (через Kafka) | Клиент: золотая запись, UCID, слияние дублей | U, D | Асинхронный | Режим coexistence: CRM заменяет локальные значения эталонными, дубли помечаются неактивными |
| F06 | MDM | FU/RB Core, Cards, Loans (через Kafka) | Кросс-ссылки UCID ↔ локальный ID | U, E | Асинхронный | Операционные системы ссылаются на единого клиента |
| F07 | MDM | FU/RB Core, Cards, Loans, CRM (через Kafka / ESB) | Продукт, Тариф, Подразделение, Сегмент | C, U | Асинхронный | Единые справочники вместо ручного ведения в каждой системе |
| F08 | FU CRM, RB CRM | MDM, CRM другого банка, DWH (через Kafka) | Согласие | C, D (отзыв) → V | CDC → асинхронный | Согласия привязаны к UCID, отзыв применяется во всех системах |
| F09 | RB Core, RB Cards, RB Loans | FU CRM (через Kafka) | Счёт, Карта, Кредит (сводка продуктов клиента) | C, U, E (UCID, код продукта FU) | CDC → асинхронный | Менеджеры FU видят продукты клиента RB в FU CRM без доступа к RB-системам |
| F10 | FU Core, FU Cards, FU Loans | FU DWH | Договор, Счёт, Вклад, Кредит, Карта, Платёж, Транзакция | R → C | Batch T+1 (существующий ETL, с реплик БД) | Работающий поток отчётности FU сохраняется без изменений |
| F11 | RB Core, RB Cards, RB Loans | FU DWH (через Kafka) | Договор, Счёт, Вклад, Кредит, Карта, Платёж, Транзакция | C → V, E (UCID, маппинг продуктов) | CDC, загрузка в DWH раз в сутки | Данные RB попадают в единую управленческую отчётность без нагрузки на RB Core |
| F12 | MDM | FU DWH (через Kafka) | Клиент (псевдонимизированный), UCID, справочники | C, U | CDC | Факты обоих банков обогащаются единым UCID и едиными кодами продуктов и подразделений |
| F13 | RB DWH | FU DWH | История RB: счета, операции, кредиты, отчётные показатели | C → V | Batch: разовая загрузка + сверка | Историческая сопоставимость управленческой отчётности |
| F14 | FU DWH | BI | Витрины: клиенты, счета, продукты, операции | A → R | Batch T+1 | Единая управленческая отчётность по двум банкам |
| F15 | FU DWH | Банк России | Регуляторная отчётность FU | A, V | Batch по регламенту | Отчётность юрлица FinUnion |
| F16 | RB DWH (загружается из RB Core, Cards, Loans, as-is) | Банк России | Регуляторная отчётность RB | A, V | Batch по регламенту | Отчётность юрлица RetailBank до его присоединения |
| F17 | Kafka/Schema Registry, MDM, ETL FU DWH, BI | DataHub | Метаданные, схемы, lineage, результаты DQ-проверок | R | Batch (ежедневно) + push из ETL | Трассируемость происхождения данных и анализ влияния изменений |
| F18 | FU CRM, RB CRM | FU Core/Cards/Loans (через ESB), RB Core/Cards/Loans (P2P) | Заявка, Договор, Клиент (с UCID) | C | Синхронный (as-is) | Существующие операционные процессы продаж сохраняются, новых P2P не создаётся |


## Integration Layer

| Компонент | Назначение |
|---|---|
| **FU ESB** | Синхронные вызовы REST/SOAP: поиск клиента в MDM, операционные вызовы FU. Для legacy-систем конвертирует форматы (Message Translator) |
| **Kafka** | Асинхронные потоки: топики по доменам (клиент, согласие, справочники, данные RB). Доставка at-least-once, идемпотентные потребители, повтор ×3, затем DLQ |
| **Debezium CDC** | Читает журнал транзакций баз FU CRM и RB CRM/Core/Cards/Loans и публикует изменения в Kafka. Системы не дорабатываются, аналитика не нагружает OLTP тяжёлыми SELECT-запросами |
| **Schema Registry** | Реестр контрактов данных для топиков Kafka |
