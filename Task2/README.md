# Task2. Мастер-системы и потоки данных

Мастер-системы для 15 ключевых сущностей в промежуточном (3 месяца) и целевом (12 месяцев) состояниях, правила владения данными, потоки данных промежуточного состояния и управление ими.

## Основные решения

- **Клиент:** мастер всех атрибутов — MDM Customer Hub. Через 3 месяца режим coexistence: клиента заводят в FU CRM и RB CRM, изменения через CDC попадают в MDM, где собирается золотая запись с UCID и сливаются дубли. Золотая запись и UCID возвращаются в CRM и операционные системы. В целевом состоянии режим centralized: клиента создают и меняют только через API MDM.
- **Справочники** (Продукт, Тариф, Подразделение, Сегмент): мастер — MDM Reference Data, с маппингом кодов RB → FU. Тарифы ведутся версиями, индивидуальные условия — часть договора.
- **Операционные сущности** (участие в договоре, договоры, счета, вклады, кредиты, карты, платежи, транзакции) остаются в профильных системах: через 3 месяца FU-системы — мастер портфеля FU, RB-системы — портфеля RB. К 12 месяцам мастера — FU Core, FU Cards, FU Loans, RB-системы выводятся. Полный номер карты не покидает PCI-зону процессинга.
- **Обращение клиента:** мастер — CRM своего банка, цель — FU CRM.
- **Согласие:** сейчас мастер — CRM своего банка с привязкой к UCID в MDM, цель — отдельный контур Consent Management.
- **Владение:** Data Owner назначается по типу клиента или продукта (ФЛ — розничный бизнес, ЮЛ и ИП — МСБ). Данные меняются только в мастер-системе, качество контролируется по пяти измерениям.
- **Integration Layer:** FU ESB — синхронные вызовы и конвертация форматов для legacy. Асинхронные потоки — Kafka + Debezium CDC + Schema Registry (Avro). RB подключается через CDC, существующие P2P RB сохраняются as-is, новых не создаётся.
- **Отчётность:** единая управленческая отчётность — в FU DWH, куда RB грузится через CDC, а история RB DWH — разовой загрузкой. Регуляторная отчётность до присоединения RB сдаётся по юрлицам: FU — из FU DWH, RB — из RB DWH.
- **Каталог:** DataHub хранит метаданные, владельцев и lineage всех потоков.
- Границы владения опираются на сервисные домены BIAN (маппинг из Task1).
