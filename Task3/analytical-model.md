# Аналитическая модель: операции по счетам и картам

Схема «звезда». Диаграмма: [diagrams/analytical-model.mmd](diagrams/analytical-model.mmd) ([SVG](diagrams/analytical-model.svg)).

Витрина отвечает на вопросы единой управленческой отчётности: обороты и число операций по продуктам, сегментам, подразделениям и каналам, сравнение портфелей FU и RB, активность клиентов. Витрина `fact_transactions` в DWH содержит операции за текущий и прошлый год, такая же модель в Gold-слое Lakehouse — за всю историю (доступ через Trino).

**Гранулярность:** одна строка — одна финансовая операция по счёту: проводка АБС или карточная операция после клиринга. Авторизации в факт не попадают, иначе операция учитывается дважды. Уникальность: код системы-источника + ID операции.

## Таблицы

| Тип таблицы | Таблица | Содержание |
|---|---|---|
| Fact | `fact_transactions` | Меры: `amount` (в валюте операции), `amount_rub`, `fee_amount_rub`, признак сторно `is_reversal`. Ключи всех измерений. Метки времени события и загрузки для контроля своевременности |
| Dimension | `dim_date` | День, неделя, месяц, квартал, год, признак рабочего дня. Используется в двух ролях: дата операции и дата проводки |
| Dimension | `dim_customer` | Псевдоним UCID, тип лица (ФЛ, ИП, ЮЛ), возрастная группа, регион, признак «клиент RB до слияния». ФИО, документов и контактов нет |
| Dimension | `dim_account` | Маскированный номер, балансовый счёт, банк-источник (FU/RB), даты открытия и закрытия, статус |
| Dimension | `dim_card` | Токен и маскированный номер, тип (дебетовая или кредитная), платёжная система, статус |
| Dimension | `dim_product` | Код продукта FU (коды RB сопоставлены через MDM), тип, линия бизнеса (розница или МСБ) |
| Dimension | `dim_branch` | Код, тип (офис, ВСП, контакт-центр), филиал, регион |
| Dimension | `dim_segment` | Код и название сегмента, линия бизнеса. В факте — сегмент клиента на дату операции |
| Dimension | `dim_channel` | Офис, мобильное приложение, веб, банкомат, POS, e-commerce |
| Dimension | `dim_operation_type` | Группа операции (платёж, перевод, покупка, снятие наличных, комиссия, проценты), направление (дебет или кредит) |
| Dimension | `dim_currency` | Код ISO, название |

Измерения строятся из справочников MDM и Silver-слоя.

## Почему модель подходит для OLAP-нагрузки

- **Простые запросы.** Каждое измерение соединяется с фактом одним JOIN. BI и аналитики строят срезы «по продукту, сегменту, месяцу» без сложных цепочек соединений.
- **Быстрые агрегации.** Факт узкий (ключи + меры) и партиционирован по месяцам даты операции: запросы за период читают только нужные партиции, SUM и COUNT идут по компактным строкам.
- **Согласованные измерения.** `dim_customer`, `dim_product`, `dim_branch`, `dim_date` используются и в других витринах (кредитный портфель, вклады), поэтому метрики сопоставимы между витринами.
- **«Звезда», а не «снежинка».** Иерархии продуктов (линия бизнеса → тип → продукт) и подразделений (банк → филиал → ВСП) небольшие, их удобнее держать в одной таблице измерения. Расхождений справочников нет, потому что источник у всех измерений один — MDM.
