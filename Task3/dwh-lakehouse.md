# DWH и Data Lakehouse

## Сравнение для FinUnion + RetailBank

| Критерий | DWH на PostgreSQL | Data Lakehouse (Iceberg + Trino) |
|---|---|---|
| Схема | Schema-on-write, строгая модель staging → core → marts | Bronze хранит данные как есть, схема применяется в Silver и Gold |
| Объём и история | Годы детальных операций двух банков — сотни миллионов строк; один узел упирается в ресурсы | Хранение на S3 масштабируется горизонтально, полная история дешевле |
| Типы данных | Структурированные таблицы | Таблицы, события, JSON, CDC-история, архивные файлы RB |
| Точность и сверка | ACID, ограничения целостности, привычная сверка с оборотно-сальдовой ведомостью АБС | ACID на уровне снимков таблиц; сверки нужно строить отдельно |
| Производительность | Быстрые запросы к витринам ограниченного объёма | Параллельные сканы больших объёмов, отсечение партиций |
| Потребители | Регуляторная и управленческая отчётность, BI | Аналитики, риск-менеджмент, антифрод, ML, BI по истории |
| Эксплуатация | Знакомо для команды FU DWH | Нужны компетенции по Iceberg, Trino, Spark и каталогу |

## Выбранный подход

| Состояние | DWH | Lakehouse |
|---|---|---|
| **3 месяца** | FU DWH на PostgreSQL: единая управленческая отчётность FU + RB. Данные RB поступают через CDC и Kafka в staging, dbt строит core и витрины. Регуляторная отчётность — по юрлицам (FU DWH, RB DWH) | Не внедряется. Архив RB DWH загружается в FU DWH разово (F13 в Task2) |
| **12 месяцев** | PostgreSQL DWH загружается из Silver. Регламентированная и управленческая отчётность по обоим юрлицам. RB DWH выведен | Единая точка входа данных в аналитику (Bronze → Silver → Gold): полная история, события, архив RB, data-продукты, ML |

## Роль Apache Iceberg и Trino

Объектное хранилище (S3 на Ceph) хранит Parquet-файлы, но таблицами не управляет.
- **Apache Iceberg** превращает набор файлов в таблицу: схема, партиции, снимки. Новая версия таблицы публикуется целиком или не публикуется вовсе, поэтому потребители не видят незавершённую загрузку. Снимки позволяют воспроизвести данные на дату закрытия периода (time travel), что нужно для аудита отчётности.
- **Trino** — распределённый SQL-движок, сам данные не хранит. Он даёт BI, аналитикам и dbt SQL-доступ к Iceberg и отсекает лишние партиции (например, читает только нужный месяц операций). Через Trino аналитики получают многолетнюю историю, которой нет в DWH, без переноса её в PostgreSQL.

## Какие данные где хранятся

| Данные | DWH | Lakehouse | Почему |
|---|---|---|---|
| Договоры, счета, вклады, кредиты (текущее состояние и история изменений) | Да | Да (Silver) | Основа отчётности; в Lakehouse — полная история для аналитики |
| Детальные операции и проводки | Текущий и прошлый год | Вся история | Сравнение год к году в DWH без перегрузки PostgreSQL; более глубокая история — через Trino |
| Остатки и обороты по счетам, кредитный портфель на дату | Вся история | Да | Регламентные расчёты требуют полной истории остатков; объём управляемый |
| Витрины управленческой и регуляторной отчётности | Да | Нет | Сертифицированные показатели, сверка с учётом, выгрузки в Банк России |
| Клиенты (псевдонимизированные), справочники MDM | Да (измерения) | Да (Silver) | Нужны обоим контурам для связи фактов |
| Карточные авторизации и события | Нет | Да | Большой поток событий для антифрода и анализа поведения; в DWH попадают только финансовые операции |
| CDC-история изменений всех систем | Нет | Да (Bronze) | Повторная обработка, восстановление происхождения данных |
| Архив RB (RB DWH, Core, Cards, Loans) | Нет | Да (Iceberg) + WORM-копия в объектном хранилище | Системы RB выведены, история нужна для запросов регулятора и аудита |
| Наборы для ML (скоринг, антифрод) | Нет | Да (Gold) | Нужны вычисления Spark и большие объёмы |

## Ограничения

**Промежуточное состояние (3 месяца)**
- Весь аналитический контур — один сервер PostgreSQL FU DWH. Загрузка RB через CDC, разовая загрузка архива RB DWH, преобразования dbt внутри PostgreSQL и запросы BI делят одни и те же ресурсы.
- Lakehouse ещё нет: карточные события, CDC-история и сырые данные RB не хранятся, повторно обработать их позже нельзя.
- Регуляторная отчётность остаётся раздельной (FU DWH и RB DWH), единой её сделать нельзя до юридического присоединения RB.

**DWH на PostgreSQL (12 месяцев)**
- PostgreSQL работает на одном узле: добавить узлы и распределить на них данные и запросы, как в MPP или Trino, нельзя. Рост возможен только за счёт более мощного сервера, а у этого пути есть предел. Поэтому детальные операции в DWH хранятся только за 2 года.
- Отчёты, которым нужна детальная история старше 2 лет, строятся не в DWH, а через Trino по Lakehouse.
- DWH загружается из Silver: если Spark, каталог Iceberg или объектное хранилище недоступны, регламентная и регуляторная отчётность задерживаются.
- DWH обновляется раз в сутки (T+1), отчётности в течение дня нет.

**Lakehouse (Iceberg + Trino)**
- ACID в Iceberg действует на уровне снимка одной таблицы. Первичных и внешних ключей и транзакций на несколько таблиц нет, поэтому финансовые сверки (проводки, остатки, итоги с АБС) строятся отдельными проверками dbt и Great Expectations.
- Скорость Trino зависит от партиционирования, размера файлов и статистики. Для частых интерактивных отчётов BI с множеством пользователей он медленнее витрин PostgreSQL.
- Потоковая запись из Kafka в Bronze создаёт много мелких файлов, а каждое изменение — новый снимок. Нужны регулярное объединение файлов (compaction), удаление старых снимков и неиспользуемых файлов, иначе падает производительность и растёт объём.
- Каталог Iceberg (Iceberg REST Catalog) — единая точка отказа: без него таблицы не доступны ни Trino, ни Spark.
- Без паспорта данных, владельцев и правил публикации по слоям Lakehouse превращается в «болото данных».
- Хранение на собственном Ceph и Kubernetes: мощности закупаются заранее. В облако выносятся только анонимизированные наборы для ML.

**Сочетание DWH и Lakehouse**
- Часть данных (договоры, счета, остатки, операции за 2 года) хранится дважды — в Silver и в DWH. Это двойной объём, два контура доступа и риск расхождения показателей DWH и Gold.
- Две платформы требуют разных компетенций: команде FU DWH нужно освоить Iceberg, Trino и Spark.
