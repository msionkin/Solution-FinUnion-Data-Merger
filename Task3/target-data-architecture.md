## Компоненты

| Компонент | Технология | Назначение | Данные |
|---|---|---|---|
| Operational Systems | FU CRM, FU Core Banking, FU Card Processing, FU Loan System, Consent Management | OLTP: мастер-системы операционных сущностей, ACID-транзакции | Договоры, счета, вклады, кредиты, карты, платежи, проводки, обращения, согласия |
| MDM | Мультидоменная MDM-платформа (Customer Hub + Reference Data), режим centralized | Золотая запись клиента и UCID, единые справочники; создание и изменение клиента только через API MDM | Клиент, Продукт, Тариф, Подразделение, Клиентский сегмент |
| Integration Layer (sync) | FU ESB (REST/SOAP) | Синхронные вызовы: API MDM, заявки CRM → Core, конвертация форматов для legacy | Запросы и ответы по клиенту, заявки, договоры |
| Integration Layer (async) | Kafka + Debezium CDC + Schema Registry (Avro) | События и CDC из журналов OLTP-баз; контракты схем; DLQ | Все изменения операционных и мастер-данных |
| Data Lakehouse | S3 на Ceph + Apache Iceberg; слои Bronze / Silver / Gold | Детальная история и события: единая точка входа данных в аналитику, data-продукты, ML | Полная история операций, карточные события, CDC-история, архив RB |
| Обработка | Spark; Kafka Connect Iceberg Sink | Потоковая запись в Bronze; batch-обработка Bronze → Silver, загрузка DWH, архивы, обслуживание таблиц | — |
| SQL-движок | Trino | SQL-доступ к Iceberg для BI, аналитиков, dbt; отделяет вычисления от хранения | — |
| DWH | PostgreSQL (staging → core → marts) | Регламентированная и управленческая отчётность, сверка с учётом | Детальные операции за текущий и прошлый год; остатки, обороты, договоры, кредиты, агрегаты — за всю историю |
| BI | FU BI + семантический слой (сертифицированные датасеты) | Дашборды и отчёты; единые формулы метрик. RB BI выведен | Витрины DWH, Gold-таблицы через Trino |
| Оркестрация | Apache Airflow | Расписание, зависимости, повторы, backfill batch-пайплайнов | — |
| Трансформации и качество | dbt (PostgreSQL, Trino) + dbt tests + Great Expectations | SQL-модели слоёв и витрин в Git, проверки качества и контрактов | — |
| Каталог данных | DataHub | Каталог, глоссарий (термины BIAN), владельцы, lineage, результаты DQ | Только метаданные |
| Объектное хранилище | S3 на Ceph (отдельные бакеты, WORM) | Документы, сканы договоров и согласий, выгрузки регулятору, архивы | Файлы |
| ML-песочница | Облако | Эксперименты и обучение моделей | Только анонимизированные наборы из Gold |

## Архитектурные принципы

1. **OLTP и OLAP разделены.** Аналитика не читает операционные базы: данные уходят только через CDC (журнал транзакций) и Kafka. BI, отчётность и ML работают только в аналитическом контуре.
2. **Данные загружаются один раз.** Все потоки в аналитику проходят через Bronze. Spark очищает их, сопоставляет с UCID и псевдонимизирует в Silver. DWH загружается уже подготовленными данными из Silver, поэтому тяжёлые вычисления не нагружают PostgreSQL, а правила очистки описаны в одном месте.
3. **Единые идентификаторы.** UCID и коды справочников из MDM используются во всех слоях и data-продуктах.
4. **Безопасность.** Bronze — изолированная зона, доступ к ней есть только у загрузки и дежурных инженеров. В Silver и дальше ПДн псевдонимизированы, ключ соответствия хранится в отдельном сервисе токенизации (Vault). Полный номер карты не покидает PCI-зону. В PostgreSQL и Trino настроены RBAC, row-level security и маскирование. В облако передаются только анонимизированные наборы после проверки на реидентификацию.
5. **Отчётность из единого места.** Регуляторная отчётность читается только из сертифицированных витрин DWH, в разрезе юрлица (FU и RB до присоединения).
6. **Трассируемость.** Каждый набор данных зарегистрирован в DataHub с владельцем. Lineage собирается автоматически из Schema Registry, Airflow (OpenLineage), dbt, Trino и PostgreSQL.
